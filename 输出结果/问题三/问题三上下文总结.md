# 问题三：入库-出库协同调度优化 — 上下文总结

## 1. 优化目标

$$\min \sum_{j} \text{flow\_time}_j = \sum_{j} (\text{完成时刻}_j - \text{到达时刻}_j)$$

- flow_time = 等待时间 + 操作时间
- 与问题二定义完全一致，区别在于同时包含入库订单和出库订单
- **目标函数值**: 40,229,327s = 7,357,359(入库) + 32,871,968(出库)

## 5. 核心算法

### 时间公式（参照问题二）

```python
T_out(x,z) = x*0.4/vx + LH[z]/vz          # 原点→(x,z)
T_between(x1,z1, x2,z2) = |dx|*0.4/vx + |dLH|/vz  # 两位间
```

### 操作时间定义

| 操作类型 | flow_time计算 | 完成时刻定义 |
|----------|--------------|-------------|
| 纯出库 | 2*T_out + T0 | 回到原点 |
| 纯入库 | T_out + T0 | 放到货位上 |
| 复合出库 | T_between(ib,ob) + T_out(ob) + T0 | 回到原点 |
| 复合入库 | T_out(ib) + T0 | 放到货位上 |

### 复合作业模式

**at_origin模式** (堆垛机在原点):
origin → ib(T_out_ib+T0) → ob(T_between+T_out_ob+T0) → origin

**not_at_origin模式** (复合继续):
ib_prev → ob(T_between_prev+T_out_ob+T0) → origin → ib_next(T_out_ib+T0)

### 调度规则

- **出库SPT**: 队列按 `min(2*T_out+T0)` 升序，选择队首可执行订单
- **入库SPT**: 队列按 `T_store=T_out+T0` 升序（单箱粒度）
- **复合决策**: 两队列均非空时优先复合；一方耗尽自动切纯操作
- **巷道隔离**: 入库空位搜索限定本巷道，出库位置选择限定本巷道

## 6. 开发过程中的关键修复

### 修复1: 巷道交叉污染 (2026-05-24)
- **问题**: `find_nearest_empty()` 为全局搜索，多台堆垛机分配到同一空位，且可跨巷道操作
- **修复**: 拆分为 `find_nearest_empty_global()` (到达时预览) 和 `find_nearest_empty_aisle()` (执行时本巷道搜索)

### 修复2: 出库默认巷道错误 (2026-05-24)
- **问题**: 材料缺货时出库订单默认分配到堆垛机1，后续补货后可能在其他巷道
- **修复**: 缺货订单放入全局 `pending_outbound` 列表；每次 `crane_free` 时检查并分配到正确巷道；执行前重新分配队列中错位订单

### 修复3: 重复crane_free事件 (2026-05-24) ⚠️
- **问题**: `handle_crane_free` 未检查堆垛机是否真正空闲。同一时刻t有多个crane_free事件时，第一个设置busy_until后，后续事件在同一t继续执行，导致多订单"并行"处理
- **影响**: 时间线出现559处重叠，flow_time被低估
- **修复**: 在 `handle_crane_free` 开头添加 `if not crane.is_idle(t): return` 守卫
- **结果**: 总流动时间从24.9M→40.2M(+61%)，时间线完全一致
